# 00 后端服务运行时关系图

```text
Client
  ↓ HTTP / RPC / gRPC / SSE
Gateway / API Server
  ↓
Business Service（Go / Python）
  ├─ Go interface / method set 决定服务实现能否注入框架
  ├─ gRPC RegisterServer 将实现对象注册到 grpc.Server
  ├─ Redis：缓存、会话、TTL、惰性删除、限流
  ├─ Kafka：事件日志、consumer group、offset、重试和 DLQ
  └─ RabbitMQ：exchange/binding 路由、TTL+DLX 延时、Lazy Queue、Federation
  ↓
Database / Object Storage / External Services
```

## 运行时关注点

- gRPC 服务能否注册成功，取决于生成接口与结构体方法集是否匹配。
- Redis TTL 适合表达临时状态，但过期删除不保证精确瞬时物理删除。
- RabbitMQ 延时队列适合业务消息触发，但不同 TTL 混在普通 FIFO 队列中可能产生队头阻塞。
- Lazy Queue 适合削峰堆积场景，代价是更依赖磁盘 IO。
- Federation 适合跨 broker 异步消息流，不等于强一致集群。
