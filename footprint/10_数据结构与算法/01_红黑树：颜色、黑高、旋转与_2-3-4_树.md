# 10.01 红黑树：颜色、黑高、旋转与 2-3-4 树

> 学习层级：中级  
> 前置知识：二叉搜索树（BST）、树的递归结构与旋转  
> 关联知识：[Linux epoll：Socket、就绪通知、实例与多线程模型](../07_Backend_Deploy_Network/13_Linux_epoll_Socket_就绪通知与多线程等待.md)（其中的 interest list 在 Linux 实现中使用红黑树）

## 1. 红黑树解决什么问题

红黑树（Red-Black Tree, RBT）是一棵**自平衡二叉搜索树**。它保留 BST 的有序规则：

```text
左子树 key < 当前节点 key < 右子树 key
```

普通 BST 若按 `1, 2, 3, 4, 5` 插入，可能退化为链表，查找、插入和删除最坏为 `O(n)`。红黑树通过节点颜色和局部修复把树高限制为 `O(log n)`，因此三种操作均为 `O(log n)`，且支持有序遍历、最小/最大值、前驱/后继与范围查询。

节点除 `key / left / right` 外有一个 `RED` 或 `BLACK` 状态位。颜色不是业务数据，而是平衡约束的编码。

## 2. 五条性质与黑高

经典定义可写为：

1. 每个节点是红色或黑色；
2. 根为黑色（主要简化定义与修复）；
3. 所有 NIL 空叶视为黑色；
4. 红节点不能有红色孩子；
5. 从任一节点到其每个后代 NIL 的路径，黑节点数相同。

第 5 条的数量称为 **black height（黑高）**。不同教材对“是否计起点/NIL”有不同计数约定；关键不在绝对数字，而在同一节点通向各 NIL 路径的黑节点数必须相等。

```text
       10(B)
       /    \
     5(R)  15(B)
     / \
   3(B) 7(B)
```

从 `10` 出发的任一路径都经过相同数量的黑节点（按统一约定计数），即黑高一致。

## 3. 颜色到底有什么用：物理高度与逻辑高度

红黑树并非“用黑高简单取代真实高度”，而是允许红节点作为一层受限的额外物理高度：

```text
路径 A：B → B → NIL
路径 B：B → R → B → NIL
```

路径 B 实际多一层，但红节点不增加黑高，所以二者仍可视为同一逻辑高度。可以把黑节点理解成推进一个正式逻辑层级，红节点理解成挂在黑父节点上的扩展/缓冲层。

红节点不能连续正是这层缓冲的上限：若允许 `B → R → R → R ...`，黑高不变而真实路径可无限变长，树会再次退化。由于每两个真实层最多只有一个红节点，最长路径不超过最短路径的两倍。

从 2-3-4 树视角更直观：红边把一个红节点与黑父节点合并为一个逻辑节点。

```text
    10(B)          [10]
    /
  5(R)       对应  [5 | 10]

  10(B)            [5 | 10 | 15]
  /   \
5(R) 15(R)
```

因此黑高近似底层 2-3-4 树的树高；颜色用一个 bit 将二叉树的物理高度与逻辑高度解耦。红色默认用于新插入节点，也正因为它不会立刻增加任一路径的黑高。

## 4. 为什么高度是 `O(log n)`

若某节点黑高为 `bh`，其子树至少含有约 `2^bh - 1` 个内部节点，因此：

```text
n ≥ 2^bh - 1
bh ≤ log₂(n + 1)
```

又因不能有连续红节点，真实树高 `h` 至多为黑高的两倍：

```text
h ≤ 2bh ≤ 2log₂(n + 1)
```

所以红黑树不要求左右子树严格等高，只保证不会歪得过分。这是它比 AVL 宽松、通常插删修复更少的原因。

| 结构 | 平衡约束 | 查找 | 插入/删除 | 适合场景 |
| --- | --- | --- | --- | --- |
| 普通 BST | 无 | 最坏 `O(n)` | 最坏 `O(n)` | 简单、数据分布可控 |
| AVL | 左右高度差最多 1 | `O(log n)`，通常更矮 | `O(log n)`，调整较敏感 | 读远多于写 |
| 红黑树 | 黑高一致且不连续红 | `O(log n)` | `O(log n)`，综合成本均衡 | 读写混合、有序索引 |

## 5. 修复工具：旋转与变色

旋转改变局部父子关系但保留 BST 中序顺序；变色修复红黑约束。

```text
左旋（在 10 处）              右旋（在 20 处）
  10                              20
    \                            /
     20          →                10
    /  \                          /  \
   15  30                        5   15
      变为                    
       20
      /  \
    10   30
      \
      15
```

插入时先按 BST 规则插入，并默认标红；这样通常不改变黑高。若父节点为黑色，直接结束；若出现红父—红子冲突，则看叔叔节点：

- **叔叔为红**：父与叔叔染黑、祖父染红，将问题上推；根最终染黑。
- **叔叔为黑/NIL**：先把折线形转成直线形，再围绕祖父旋转并重新着色。

四种形状的旋转方向可归纳为：

| 形状 | 操作 |
| --- | --- |
| LL | 祖父右旋 |
| RR | 祖父左旋 |
| LR | 父左旋，再祖父右旋 |
| RL | 父右旋，再祖父左旋 |

例如 `10(B) → 5(R) → 3(R)` 是 LL：先在 `10` 右旋，再让新子树根变黑、原祖父变红。旋转解决结构倾斜，变色解决红红冲突；两者常需配合。

删除比插入复杂：删除红节点一般不改变黑高，删除黑节点可能使一条路径少一个黑节点，形成常称的“double black（双重黑）”问题。修复根据父、兄弟及兄弟孩子的颜色，通过变色、旋转，把额外黑色向上转移或消除。实践中应直接采用经过验证的库实现，除非确有实现数据结构的需求。

## 6. 工程上的定位

查找只遵循 BST 比较规则，颜色只服务于插入、删除和修复。常见有序映射/集合实现包括 Java `TreeMap`、`TreeSet` 以及许多 C++ 标准库实现中的 `map`/`set`；具体标准库内部实现仍以版本和实现为准。

一句话记忆：**红黑树用“黑高一致 + 红红禁止”保证最长路径至多是最短路径的两倍；红色是受限的高度缓冲，也是 2-3-4 树一个逻辑节点的扩展部分。**
