# 03.15 附：通用学习与异步服务排查模板

> 说明：本文件合并原来散落在各知识点中的重复排查段。第一部分适用于所有主题；第二部分仅适用于异步与 FastAPI 服务。

## 1. 通用理解框架

学习任一主题时，依次回答：

1. 它解决的核心问题是什么？
2. 输入、输出和中间状态分别是什么？
3. 它改变了什么运行时行为？
4. 正常路径与失败路径分别如何工作？
5. 它依赖哪些前置知识，又连接哪些后续知识？

常见学习误区：

- 只背名词，不知道它在完整链路中的输入、输出和失败模式；
- 只看正常路径，忽略异常、超时、权限、重复和可观测性；
- 把相邻概念混用，导致设计或排查时定位错误。

跨专题关系可结合根目录的 `00_总体索引.md` 和 `00_总体知识网络图.md` 查看。

## 2. 通用排查顺序

```text
复现问题并保留原始输入
  ↓
确认运行环境、版本和配置
  ↓
定位输入、输出和第一个偏离预期的中间状态
  ↓
检查异常是否被捕获、转换或吞掉
  ↓
缩小为最小示例
  ↓
修正后验证正常路径、边界条件和失败路径
```

调试时应优先记录稳定字段，例如步骤名、请求 ID、业务对象 ID、耗时和异常堆栈，而不是只输出难以搜索的自由文本。

## 3. 异步服务的四个观察维度

异步、文件流、上下文管理器和后台任务主要涉及运行时行为：

1. **生命周期**：对象、协程、文件流和连接何时创建、挂起、恢复和释放；
2. **阻塞点**：网络 I/O、文件 I/O、数据库查询、同步 SDK 和 CPU 计算在哪里占用线程；
3. **错误传播**：异常是直接抛出、被 Task 包装、被转换，还是在后台任务中无人观察；
4. **可观测性**：日志、trace ID、task ID 和结构化字段能否还原一次执行路径。

## 4. 最小异步调试骨架

```python
import logging
from collections.abc import Awaitable
from typing import TypeVar

T = TypeVar("T")

logging.basicConfig(filename="app.log", level=logging.INFO)

async def run_step(name: str, awaitable: Awaitable[T]) -> T:
    logging.info("start step=%s", name)
    try:
        result = await awaitable
        logging.info("done step=%s result=%r", name, result)
        return result
    except Exception:
        logging.exception("failed step=%s", name)
        raise

# 用法：
# result = await run_step("retrieve", retriever(query))
```

需要注意：Python 3.8 及之后的 `asyncio.CancelledError` 直接继承 `BaseException`，因此上面的 `except Exception` 不会吞掉任务取消；清理仍应放入业务协程的 `finally`。

## 5. 异步/FastAPI 专项检查

- **是否真的执行**：coroutine 是否被 await 或创建成 Task，生成器是否被消费，上下文是否真正进入；
- **是否阻塞事件循环**：`async def` 内是否执行同步数据库、文件、网络 SDK 或 CPU 密集代码；
- **异常是否可见**：后台 Task 是否保留引用并收集结果，BackgroundTasks/worker 是否记录失败；
- **资源是否关闭**：文件、数据库连接、上传流、Session 和 client 的所有者是谁；
- **背压是否贯通**：Queue 是否有界，生产者是否真正等待，超时和取消是否传到上游；
- **协议命名是否真实**：在 `yield` 前发送的事件不能声称后续 checkpoint 已完成。

## 6. 工程落地要点

- 先明确哪些函数必须异步，哪些只是普通 CPU 计算；
- 大文件优先分块处理，但要保证整个下游链路不会再次一次性读入内存；
- 对生成器、上下文管理器、Task 和后台任务明确“谁创建、谁消费、谁关闭、异常从哪里冒出”；
- 可靠长任务使用持久化队列和独立 worker，不把进程内 BackgroundTasks 当作任务系统；
- BusinessState 与 Queue、Session、client 等 RuntimeContext 分层。

## 7. 小型练习与表达模板

```python
async def safe_call(name, func, *args, **kwargs):
    try:
        return await func(*args, **kwargs)
    except Exception as exc:
        print(f"[{name}] failed:", repr(exc))
        raise
```

练习：把一个异步调用包在 `safe_call` 中，分别触发正常结果、业务异常、超时和取消，观察异常在哪里出现、`finally` 是否执行。

回答某个 Python 运行时主题时，可以按下面的顺序组织：

```text
它解决什么问题
→ 改变了什么运行时行为
→ 什么时候真正执行
→ 正常与异常路径
→ 项目中如何验证和排查
```
