# Go GC：三色标记与混合写屏障

> 所属分类：Go / Gin / Runtime  
> 修订版本：v11 审查修订版  
> 质量要求：本文件只解释本知识点，不复用其他知识点的原理段；示例尽量给出代码、伪代码、命令或配置。

## 1. 总体性概念

Go GC 使用三色标记和混合写屏障，在并发标记期间防止对象引用变化导致误回收。


## 2. 原理性解释

- 白色未访问，灰色待扫描，黑色已扫描。
- 写屏障在指针变更时补充标记。
- 删除旧引用时需保护旧对象可能引用的子图。
- 标灰不代表永不回收，只是本轮避免漏扫。

### 混合写屏障解决的是并发 GC 下的漏标问题

三色标记中，白色表示未扫描，灰色表示待扫描，黑色表示已扫描。如果用户程序和 GC 并发运行，黑色对象可能新增对白色对象的引用，导致白色对象明明可达却没被扫描，出现误回收。写屏障就是在指针写入/删除时插入额外标记逻辑，维持三色不变式。

你问“删除原本引用为什么要把原本被引用的标记成灰色”，核心是防止某个对象因为引用被删除后，其内部子对象还没来得及被扫描就丢失路径。

## 3. 机制流程

1. root 标灰。
2. 扫描灰对象。
3. 对象变黑。
4. 写屏障处理并发修改。
5. 清扫白对象。

### GC 流程抽象

```text
STW 短暂停顿（sweep termination），开启写屏障
  ↓
从 root 扫描，灰色队列推进
  ↓
并发标记：扫描灰色对象，标黑，并把子对象标灰
  ↓
处理写屏障记录
  ↓
短暂 STW（mark termination）：完成标记终止
  ↓
关闭写屏障，并发清扫白色不可达对象
```

Go 的 GC 目标不是“完全无停顿”，而是把停顿压短（一轮 GC 有两次短 STW），同时让并发标记与用户 goroutine 交替运行。

> 版本演进：Go 1.26（2026-02）默认启用 Green Tea GC，标记-清扫从“逐对象追指针”改为按 span 批量扫描，GC 开销普遍降低 10-40%。三色抽象与混合写屏障仍是理解 Go GC 的概念基础，但“逐个扫描灰色对象”的实现细节在新版本已按内存局部性重排。

## 4. 类比理解

像查户口时有人搬家，写屏障负责补登记。

## 5. 应用举例 / 代码或伪代码

```go
old := A.child
A.child = nil
writeBarrier(old) // 防止 old 子图在本轮漏扫
```
