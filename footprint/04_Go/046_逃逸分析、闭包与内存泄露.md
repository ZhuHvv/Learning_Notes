# 逃逸分析、闭包与内存泄露

> 所属分类：Go / Gin / Runtime  
> 修订版本：v9 昨日今日增量版  
> 质量要求：本文件只解释本知识点，不复用其他知识点的原理段；示例尽量给出代码、伪代码、命令或配置。

## 1. 总体性概念

逃逸分析决定变量在栈还是堆；内存泄露是对象不再需要却仍被引用。二者不是一回事。


## 2. 原理性解释

- 返回局部变量指针会逃逸。
- 闭包捕获外层变量可能逃逸。
- 赋给全局变量可能逃逸。
- 逃逸增加 GC 压力但不是泄露。
- 泄露通常由长期引用导致。

### 逃逸分析决定变量放栈还是堆

返回局部变量指针、把局部变量赋给全局变量、闭包捕获外部变量，都可能让变量生命周期超过当前函数栈帧，因此编译器会让它逃逸到堆。逃逸不是错误，只是可能增加 GC 压力。

内存泄漏则不同：泄漏是对象已经不再需要，但仍被引用导致无法回收。逃逸是分配位置变化；泄漏是生命周期管理错误。

## 3. 机制流程

1. 编译器分析生命周期。
2. 函数内使用放栈。
3. 跨函数生命周期放堆。
4. GC 回收不可达堆对象。

### 逃逸排查流程

```bash
go build -gcflags='-m' ./...
```

```go
func makePtr() *int {
    x := 10
    return &x // x 逃逸到堆
}
```

优化时不要盲目追求“零逃逸”。先看 pprof、分配热点和延迟指标，再决定是否通过减少闭包捕获、复用 buffer、避免大对象接口装箱等方式优化。

## 4. 类比理解

逃逸像文件被带出办公室；泄露像没用的文件仍锁在柜子里。

## 5. 应用举例 / 代码或伪代码

```go
func Ptr() *int {
    x := 10
    return &x // x 必须逃逸
}

func Counter() func() int {
    n := 0
    return func() int { n++; return n }
}
```

## 6. 你在讨论中的理解推进

你问逃逸和泄露是否一回事；结论是分配位置变化 vs 无法回收。
