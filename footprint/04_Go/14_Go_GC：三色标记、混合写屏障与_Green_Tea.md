# 04.14 Go GC：三色标记、混合写屏障与 Green Tea

> 所属主线：Go Runtime 与内存  
> 难度：深入  
> 前置知识：逃逸分析、堆与 span 分配  
> 后续知识：GC 调优、内存限制与性能分析

## 1. 总体性概念

Go GC 使用三色标记和混合写屏障，在并发标记期间防止对象引用变化导致误回收。


## 2. 原理性解释

- 白色未访问，灰色待扫描，黑色已扫描。
- 写屏障在指针变更时补充标记。
- 删除旧引用时需保护旧对象可能引用的子图。
- 标灰不代表永不回收，只是本轮避免漏扫。

### 混合写屏障解决的是并发 GC 下的漏标问题

三色标记中，白色表示未扫描，灰色表示待扫描，黑色表示已扫描。如果用户程序和 GC 并发运行，黑色对象可能新增对白色对象的引用，导致白色对象明明可达却没被扫描，出现误回收。写屏障就是在指针写入/删除时插入额外标记逻辑，维持三色不变式。

删除旧引用时保护旧对象，核心是防止该对象及其内部子图尚未完成扫描就失去可发现路径。

## 3. 机制流程

1. root 标灰。
2. 扫描灰对象。
3. 对象变黑。
4. 写屏障处理并发修改。
5. 清扫白对象。

### GC 流程抽象

```text
STW 短暂停顿（sweep termination），开启写屏障
  ↓
从 root 扫描，灰色队列推进
  ↓
并发标记：扫描灰色对象，标黑，并把子对象标灰
  ↓
处理写屏障记录
  ↓
短暂 STW（mark termination）：完成标记终止
  ↓
关闭写屏障，并发清扫白色不可达对象
```

Go 的 GC 目标不是“完全无停顿”，而是把停顿压短（一轮 GC 有两次短 STW），同时让并发标记与用户 goroutine 交替运行。

> 版本演进：Go 1.26（2026-02）默认启用 Green Tea GC。它主要通过改善小对象标记与扫描时的内存局部性和 CPU 可扩展性来降低开销；官方预计，在大量使用 GC 的真实程序中，GC 开销可能下降约 10–40%，具体收益依工作负载而异。三色抽象与混合写屏障仍是理解正确性的概念基础，但不应把新实现简化成“整个标记-清扫算法都改成按 span 扫描”。

## 4. 类比理解

像查户口时有人搬家，写屏障负责补登记。

## 5. 应用举例 / 代码或伪代码

```go
old := A.child
A.child = nil
writeBarrier(old) // 防止 old 子图在本轮漏扫
```

## 6. 边界与排查

- 写屏障是 runtime 在指针写入路径插入的机制，业务代码不直接调用示例中的 `writeBarrier`。
- 三色是用于推理可达性的抽象，不代表对象头中永久保存“颜色”。
- 内存占用高不一定意味着 GC 有错误；还要区分存活堆、临时分配速率、内存碎片和 runtime 尚未归还给操作系统的页。
- 调优时优先观察 `GODEBUG=gctrace=1`、runtime metrics 和 pprof，再评估 `GOGC` 或内存限制。
