# 数据库选型：SQL、MongoDB、Redis、向量库的分工

## 1. 总体性概念

SQL、MongoDB、Redis、向量库分别面向事务事实、灵活文档、高速临时状态、语义相似检索。


## 2. 原理性解释

- SQL 适合核心数据和事务。
- MongoDB 适合半结构化文档。
- Redis 适合缓存、会话、限流和临时映射。
- 向量库保存 embedding 和 metadata。
- 复杂系统常混用多种存储。

### 数据库选型要看数据模型、访问模式和一致性要求

SQL 适合强结构、事务和复杂查询；MongoDB 适合文档结构灵活、聚合对象自然存储；Redis 适合高性能缓存、会话、计数器、临时状态；向量库适合语义相似度检索。选型不是“谁更高级”，而是看读写模式和一致性边界。

例如 RAG 系统中，文档元数据可在 SQL/MongoDB，chunk embedding 在向量库，热门查询结果在 Redis，任务状态也可以在 Redis。

## 3. 机制流程

1. 识别数据形态。
2. 确定主存储。
3. 设计索引/缓存。
4. 设计一致性和过期策略。

### 选型决策流程

```text
是否需要事务和复杂 JOIN？→ SQL
数据结构是否经常变化且以文档整体读写？→ MongoDB
是否是短生命周期高频读写状态？→ Redis
是否按语义相似度召回？→ 向量库
```

真实系统常是组合使用，而不是只选一种数据库。
