## 1. 总体性概念

MongoDB 用文档存储半结构化数据，schema 灵活但仍需要应用层建模。


## 2. 原理性解释

- 文档类似 JSON，可嵌套。
- 灵活 schema 不等于无约束。
- 适合整体读取和字段变化快场景。
- 高频查询字段仍需索引。

### MongoDB 的文档模型适合“聚合对象”

MongoDB 用 BSON 文档存储数据，一个文档可以包含嵌套对象和数组。它适合结构灵活、以对象整体读写为主的场景，例如用户配置、日志事件、内容草稿。它不适合需要大量跨集合 JOIN 和强事务复杂关系的核心账务场景。需要说明的是，MongoDB 4.0+ 已支持多文档 ACID 事务（4.2+ 支持分片事务），并非没有事务能力；但关系密集、强约束的核心账务仍以关系型数据库为宜。

```json
{"user_id": 1, "profile": {"name": "Tom"}, "tags": ["ai", "go"]}
```

## 3. 机制流程

1. 设计 collection。
2. 插入文档。
3. 建立索引。
4. 查询/更新。

### MongoDB 设计流程

```text
从查询模式出发
  ↓
决定哪些字段嵌入，哪些字段引用
  ↓
建立索引
  ↓
控制文档大小和数组增长
  ↓
必要时使用聚合管道
```

文档数据库不是“不需要 schema”，而是 schema 从数据库强约束转移到了应用设计和数据治理中。
