# 正向代理与反向代理

> 所属分类：Backend / Deploy / Network  
> 修订版本：v11  
> 质量要求：本文件只解释本知识点，不复用其他知识点的原理段；示例尽量给出代码、伪代码、命令或配置。

## 1. 总体性概念

正向代理代理客户端访问外部资源；反向代理代理服务端接收外部请求并转发内部服务。


## 2. 原理性解释

- 正向代理隐藏客户端。
- 反向代理隐藏服务端。
- 反向代理可做负载均衡、TLS 终止、路径转发。
- SSE 经过代理要注意 buffering。

### 正向代理代理客户端，反向代理代理服务端

正向代理是客户端为了访问外部资源而使用的代理，目标服务器通常不知道真实客户端；反向代理部署在服务端入口，客户端访问的是代理，由代理转发到后端服务。Nginx、网关、负载均衡常属于反向代理。

```text
正向代理：Client → Proxy → Internet
反向代理：Client → Gateway/Nginx → Backend Services
```

## 3. 机制流程

1. 客户端请求代理。
2. 代理转发。
3. 目标服务响应。
4. 代理返回。

### 反向代理请求流程

```text
用户访问域名
  ↓
DNS 解析到 Nginx/网关
  ↓
TLS 终止、鉴权、限流、日志
  ↓
按 path/host 转发到后端服务
  ↓
返回响应
```

部署 SSE/WebSocket 时要特别检查反向代理缓冲、超时和协议升级配置。

## 4. 类比理解

正向代理像代购，反向代理像商场前台。

## 5. 应用举例 / 代码或伪代码

```nginx
location /api/ {
    proxy_pass http://backend:8080/;
}
location /stream/ {
    proxy_pass http://backend:8080/stream/;
    proxy_http_version 1.1;      # Nginx 默认用 HTTP/1.0 连上游，长连接/分块传输需显式指定 1.1
    proxy_buffering off;
    proxy_read_timeout 1h;       # 默认读超时仅 60s，SSE 长连接空闲超过后会被断开
}
```

## 6. 你在讨论中的理解推进

你问正向和反向代理；关键是代理站在客户端侧还是服务端侧。
