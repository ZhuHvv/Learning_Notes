# 沙箱、权限与工具执行安全

## 1. 总体性概念

沙箱和权限控制限制 Agent 工具执行范围，防止越权、误操作和注入。


## 2. 原理性解释

- 工具描述不是安全边界。
- 代码执行要限制文件、网络、CPU、内存、时间。
- 数据库工具要最小权限。
- 高风险操作要 allowlist 或人工确认。
- 所有工具调用要审计日志。

### 沙箱和权限控制是工具型 Agent 的安全边界

当 Agent 能执行代码、读写文件、访问网络或调用业务系统时，必须限制权限。沙箱的目标是把可执行行为限制在允许范围内，例如文件路径白名单、网络访问限制、超时、资源配额、命令黑名单和审计日志。

```text
LLM 决定动作 ≠ 系统必须执行动作
```

中间必须有 policy layer 判断动作是否安全、是否需要用户确认、参数是否越权。

## 3. 机制流程

1. 模型选择工具。
2. 权限层校验。
3. 参数过滤。
4. 沙箱执行。
5. 记录审计。

### 工具执行安全流程

```text
模型提出 tool_call
  ↓
Schema 校验
  ↓
权限策略检查
  ↓
路径/参数规范化
  ↓
沙箱中执行，限制 CPU/内存/时间
  ↓
记录审计日志
  ↓
返回脱敏结果
```

对于删除文件、发邮件、付款、修改数据库等高风险动作，应要求显式用户确认，并提供可回滚或审计机制。

## 4. 类比理解

给 Agent 工具像给实习生系统权限，必须最小权限和留痕。

## 5. 应用举例 / 代码或伪代码

```python
def run_command(cmd):
    parts = shlex.split(cmd)
    # 注意：解释器（python 等）/包管理器不应进白名单——放行解释器等于放行任意代码；
    # 若必须提供，需在嵌套沙箱中执行。
    if parts[0] not in {"ls", "cat"}:
        raise PermissionError()
    return subprocess.run(parts, timeout=5, capture_output=True, text=True).stdout
```

## 6. 你在讨论中的理解推进

你在 @tool、eval、文件上传等问题中都触及安全边界；工具越强，限制越重要。
