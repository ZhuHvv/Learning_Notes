## 2. 学习方式与排序依据

- 沿用 Redis 的节奏。先讲清一个机制，留出提问时间。疑问解决后挑 1～2 道机制题，一次问一道。能独立解释就推进，有分歧就用最小代码例子厘清，再记下需要回访的条件。
- 顺序兼顾后端与游戏服务器面试的常见追问、知识依赖和出错的工程代价。先掌握复制与共享，才能讲清切片和接口；先知道 goroutine 在等什么，再进调度器读唤醒路径。并发控制、调度和 GC 是面试核心，排在后面的核心模块也值得精学。
- 语言行为查规范，运行时源码固定看 **Go 1.26.0**，与本机工具链和已有 GC 笔记一致。遇到 map 布局、切片扩容、调度策略等问题，先说程序可依赖的保证，再说该版本怎样实现。做实验时记下工具链、平台、关键参数与观察结果。[Go 1.26.0 语言规范](https://github.com/golang/go/blob/go1.26.0/doc/go_spec.html)

## 3. 模块与建议顺序

“基础”先解决后续反复用到的概念，“核心”对应常见面试追问和工程决策，“综合”要求把现象与证据连起来，“选学”按岗位或项目需要展开。优先级是备考判断，未统计题库频率。

| 编号 | 模块 | 学什么 | 主要前置 / 定位 |
|---|---|---|---|
| 01 | 值、指针与函数传参 | 零值、赋值与传参、数组与结构体复制、指针解引用；用嵌套字段说明一次复制后哪些数据仍共享 | 起点 · 基础 |
| 02 | string、数组与 slice | 字节与 rune、下标与 range；切片的底层数组、长度与容量，切片表达式、append、copy、扩容和大数组滞留 | 01 · 核心 |
| 03 | map 的语义与实现 | 键的可比较性、零值、查找与删除、遍历顺序、并发访问边界；跟踪一次键查找怎样按哈希定位到表和组、处理冲突，插入时何时需要增长 | 01～02 · 核心 |
| 04 | 方法、接口与 nil | 值/指针接收器、方法集、嵌入、隐式实现；接口的动态类型和值、类型断言、接口比较及 typed nil | 01 · 核心 |
| 05 | 函数、闭包、defer 与错误 | 闭包捕获变量、循环变量的版本语义；defer 实参求值与执行顺序、命名返回值；error 包装、errors.Is/As、panic 展开与 recover 的生效位置 | 01、04 · 核心 |
| 06 | goroutine、channel 与 select | 从启动到退出；无缓冲交接、有缓冲队列、满/空等待与唤醒；nil/已关闭 channel、谁负责关闭、select 的可运行分支 | 01、05 · 核心 |
| 07 | 内存模型与同步 | 用 happens-before 推导可见性；Mutex、RWMutex、atomic、WaitGroup、Once 的职责；单一所有者和加锁共享，普通 map 的保护范围 | 03、06 · 核心 |
| 08 | Context、取消与并发生命周期 | deadline 和取消传播，生产者/消费者退出，阻塞发送与 goroutine 泄漏；有界并发、等待退出和错误传递 | 05～07 · 核心 |
| 09 | G/M/P 调度与网络唤醒 | G、M、P 各自持有什么，运行队列、工作窃取与抢占；沿 channel 等待、网络等待和阻塞系统调用追踪 G 的状态及 M/P 的去向 | 06～08 · 核心 |
| 10 | 栈、逃逸与内存分配 | goroutine 栈增长，对象生命周期与逃逸分析，内联对观察结果的影响；按对象大小追踪分配路径，理解 mcache、mcentral、mheap 和 span | 01～02、09 · 核心 |
| 11 | GC、写屏障与内存目标 | 根与可达性、并发标记、STW、写屏障、清扫；用具体指针变更解释漏标风险；串起分配速率、存活堆、GOGC、GOMEMLIMIT 与 CPU 开销 | 09～10 · 核心 |
| 12 | 并发与性能诊断 | 按症状选 race detector、benchmark、pprof 或 trace；区分累计分配与存活内存、CPU 热点与阻塞时间，做单变量复核 | 06～11 · 综合 |
| 13 | 泛型、反射与构建边界 | 类型参数、约束和类型集；接口分派与泛型的适用场景，反射的类型、值与可设置性。按项目再补包初始化、module、构建标签和 unsafe 的使用前提 | 04～05 · 选学 |

## 4. 阶段考察与源码入口

| 学完 | 用什么问题考察 | 怎么核对 |
|---|---|---|
| 01～03 | 两个切片共享底层数组。分别让 append 有剩余容量和必须扩容，随后修改同一位置，另一个切片各会读到什么？再跟踪一次哈希碰撞后的 map 查找。 | 先画长度、容量和元素位置。切片看 `src/runtime/slice.go`，map 看 `src/internal/runtime/maps/`。旧笔记或面试题若提到桶、溢出桶，注明所讲版本。[Go 官方 map 设计说明](https://go.dev/blog/swisstable) |
| 04～05 | 函数声明返回 error，返回一个值为 nil 的具体错误指针，调用方为何进入错误分支？改成返回未包装的 nil 后再推导一遍。 | 标出接口的动态类型和值，再用最小程序比较两条返回路径。 |
| 06～08 | 同一玩家的请求并发到达，`count++` 怎样丢更新？分别用一把共享锁和一个拥有状态的 goroutine 推演。下游提前退出时，谁让阻塞发送者结束？ | 给出两条执行时序，指出同步关系、锁的范围和退出责任，再用 `go test -race` 检查实际跑到的路径。可复用模拟面试第 11～14、35～36 题。[Go 内存模型](https://go.dev/ref/mem) · [模拟面试记录](../游戏服务器中级开发_模拟面试逐题整理_2026-11-16.md) |
| 09～11 | 一个 goroutine 等网络数据时，其他 goroutine 怎样继续运行？另一例中，小切片仍引用大数组，强制 GC 后为何还占内存？ | 第一题画 G/M/P 与就绪唤醒，入口是 `src/runtime/proc.go` 和 `netpoll.go`；第二题从对象引用画到 GC 根，再查存活堆。[Go GC 指南](https://go.dev/doc/gc-guide) |
| 12～13 | 对象复用让每次请求的分配数降低，为什么服务尾延迟仍可能上升？若组件需要适配多种消息类型，何时值得引入泛型？ | 前者设计固定负载下的 benchmark，配合锁竞争或调度证据；后者比较调用方需要的操作与约束表达能力。 |
