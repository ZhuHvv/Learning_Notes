# Go 学习 01 · 值、指针与函数传参

## 结构体按值传参，切片元素为何仍共享

调用 change(player) 时，实参的值赋给独立的形参 p。HP 的整数值和 Items 的切片值都被复制。切片值描述底层数组的一段范围，所以复制后两份切片起初指向同一组元素。

```go
package main

import "fmt"

type Player struct {
    HP    int
    Items []int
}

func change(p Player) {
    p.HP = 80
    p.Items[0] = 9
    p.Items = []int{7, 8}
    fmt.Println("change", p.HP, p.Items)
}

func main() {
    player := Player{HP: 100, Items: []int{1, 2}}
    change(player)
    fmt.Println("main", player.HP, player.Items)
}
```

| 执行后 | 调用方 player | 函数内 p |
|---|---|---|
| 刚进入函数 | 100，数组 A [1 2] | 100，数组 A [1 2] |
| p.HP = 80 | 100，A [1 2] | 80，A [1 2] |
| p.Items[0] = 9 | 100，A [9 2] | 80，A [9 2] |
| p.Items = []int{7, 8} | 100，A [9 2] | 80，数组 B [7 8] |

Go 1.26.0，windows/amd64，使用 go run，无额外编译参数。实际输出：

```text
change 80 [7 8]
main 100 [9 2]
```

依据为 [Go 1.26.0 规范](https://github.com/golang/go/blob/go1.26.0/doc/go_spec.html) 的 Calls 与 Slice types 两节。本节核对了规范并运行了示例。

## 练习与复述

- 数组字段题：把 Items 改为 [2]int 后，回答调用方读到 [1 2]，并指出结构体复制时数组的两个元素也被复制。
- 指针传参题：回答调用方 HP 为 80。形参先持有调用方地址的副本，p.HP = 80 写入原对象；p 改指向新对象，后续写入发生在新对象上。
- 解引用与零值：对 *Player 类型的 p，字段选择 p.HP 是 (*p).HP 的简写。var p *Player 的零值是 nil，此时访问 p.HP 会 panic，这题判断正确。var a Player 则得到一个结构体，各字段取各自零值。
