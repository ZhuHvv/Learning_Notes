# 00 理解推进轨迹

本文件保留你在讨论中的核心理解推进，按主题压缩整理。

## 1. Transformer / LLM

- 起点：你把 Q/K/V 理解为“关注什么、提供什么、具体信息值”。
- 修正：Q 更像当前 token 发出的查询，K 是其它 token 可匹配的索引，V 是被加权聚合的信息内容。
- 推进：进一步区分 Encoder、Decoder、Decoder-only、Causal Mask、Cross Attention 与 RAG Embedding 的不同用途。

## 2. Agent / ReAct / Reflection / Memory

- 起点：你将 Agent 理解为 LLM 端到端完成任务。
- 推进：你逐步区分了 ReAct、Plan-and-Execute、Multi-Agent、Reflection、Memory、IterResearch。
- 修正：ReAct 不是所有 Agent 的统称；Reflection 不是重新回答，而是基于执行轨迹复盘；长期记忆不是简单保存聊天记录，而是结构化检索和筛选。
- 已补充：Generative Agents 文件包含 memory stream、relevance/recency/importance 检索、reflection 和 insight 写回。

## 3. Python / FastAPI / 异步

- 起点：你理解 async 只是把函数变成异步函数。
- 推进：进一步明确 await 才是让出控制权的关键；UploadFile 与 bytes 的区别在于内存占用和流式处理；上下文管理器的 yield 只有进入/消费时才执行。
- 新连接：Go 异步讨论帮助你把 Python async/await 与 Go goroutine 模型进行对比。

## 4. Go / Gin / Context / 并发

- 起点：你通过 Gin Handler、BasicAuth、Session、闭包注入理解后端接口。
- 推进：进一步理解 Context 取消、超时、WithValue、闭包、逃逸分析、GC、mcache/mcentral/mheap 等运行时机制。
- 今日新增 1：围绕 goroutine 数量与性能，理解 Go 的轻量并发不是无限并发，必须考虑调度成本、CPU 核数、下游资源和 goroutine 泄露。
- 今日新增 2：通过 channel 关闭、只读 channel、select default、关闭 channel 后无限循环等问题，理解 channel 的关闭语义和“读就绪”。
- 今日新增 3：从 `sync.Mutex.Lock()` 与 `TryLock()` 推进到悲观锁、乐观锁、CAS 和数据库 version 字段的并发控制模型。
- 今日新增 4：把 Python async/await 与 Go 的 goroutine/channel/select/context 进行对比，明确 Go 没有 async 关键字，但有完整的运行时并发机制。

## 5. 数据库 / Redis

- 起点：你询问 Redis 时间存储、HyperLogLog、SQLite、索引等概念。
- 推进：逐步形成 SQL、MongoDB、Redis、向量库分工意识，并理解 Redis Cluster、Sentinel、复制、IO Threads、限流与临时状态映射。
- 新连接：乐观锁/悲观锁知识可以延伸到数据库事务、version 字段、Redis Lua 原子扣减和分布式状态控制。

## 6. 消息队列 / Kafka / RabbitMQ

- 起点：你从“消息分发是什么”开始，先理解生产者、队列、消费者、消费组这些基本角色。
- 推进 1：你明确 Kafka 的 offset 属于 partition，不同 consumer group 对同一 topic 有各自独立 offset；同一 group 内同一 partition 通常只由一个 consumer 处理。
- 推进 2：你进一步追问“一条消息会不会被多个 consumer 处理”，最终形成判断：不同 group 会各自处理；同一 group 正常不并发重复，但崩溃、rebalance、offset 未提交会导致重复处理。
- 推进 3：你把 consumer 业务失败与 consumer 断连区分开：断连由 group coordinator 和 offset 恢复处理；业务失败需要 consumer 端主动设计 retry topic、DLQ 和幂等。
- 推进 4：你追问 leader broker 挂掉后的机制，进一步区分了 partition leader/follower、ISR、KRaft controller 元数据管理、follower fetch 进度和新 leader 从 ISR 选举。
- 推进 5：补充 key 与热分区后，你把 partition 理解为顺序性、并行度和负载均衡的共同边界。
- RabbitMQ 方向：你已理解 vhost、exchange、queue、binding、routing key/binding key 共同决定业务消息路由。

## 7. 后端部署 / 网络 / 可观测性

- 起点：你从 Docker Desktop、Compose、DNS、代理、SSE 等具体问题切入。
- 推进：逐步形成服务运行时视角：请求进入服务，经由应用层、数据层、异步层、部署层和监控层共同完成稳定运行。
