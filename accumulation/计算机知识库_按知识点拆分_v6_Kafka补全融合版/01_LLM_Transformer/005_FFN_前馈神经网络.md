## 1. 总体性概念

FFN 是 Transformer block 中对每个 token 独立执行的非线性变换；attention 负责信息交互，FFN 负责信息加工。


## 2. 原理性解释

- FFN 通常是 hidden -> intermediate -> hidden。
- 激活函数引入非线性。
- 它不直接做 token 间通信。
- 很多模型参数大量集中在 FFN。

### FFN 为什么放在 Attention 后面

Attention 解决的是 token 之间的信息交换，但它主要是加权求和，表达上偏线性组合。FFN 则对每个 token 的 hidden 向量单独做非线性变换，相当于把刚刚从上下文收集来的信息进一步加工、筛选和重编码。

典型 FFN 是两层线性层加激活函数，中间维度通常比 hidden size 大，例如 `4 * hidden_size`。这相当于先把特征投影到更高维空间里展开，再压回原维度。

```python
def ffn(x):
    return W2 @ gelu(W1 @ x + b1) + b2
```

所以 FFN 的作用不是“让 token 之间再交流一次”，而是“每个 token 对自己已经融合的上下文信息做深加工”。

## 3. 机制流程

1. attention 输出上下文向量。
2. LayerNorm。
3. FFN 升维、激活、降维。
4. 残差相加。

### 一层 Transformer Block 的完整顺序

现代模型常用 Pre-LN 结构：

```text
x
 ├─ LayerNorm → Self-Attention → Residual Add
 ↓
x'
 ├─ LayerNorm → FFN → Residual Add
 ↓
out
```

其中 residual connection 让模型可以保留原信息，LayerNorm 稳定训练，FFN 提供非线性表达能力。排查模型结构时，要区分：Attention 的复杂度主要与 `seq_len²` 有关；FFN 的计算量主要与 `hidden_size * intermediate_size` 有关。

## 4. 类比理解

attention 像收资料，FFN 像个人整理资料并形成新表达。

## 5. 应用举例 / 代码或伪代码

```python
class FFN(nn.Module):
    def __init__(self, h=768, mid=3072):
        self.w1 = nn.Linear(h, mid)
        self.w2 = nn.Linear(mid, h)
    def forward(self, x):
        return self.w2(F.gelu(self.w1(x)))
```

## 10. 更细的工程拆解

理解 **FFN 前馈神经网络** 时，不要只停留在“名词解释”，而要追踪张量和信息流：

1. **输入形态**：一段文本先变成 token id，再查 embedding table 得到向量。
2. **中间变换**：Transformer 层反复做注意力聚合、残差连接、归一化和 FFN 非线性变换。
3. **输出用途**：生成模型会把最后一层 hidden state 投影到词表 logits；Embedding/RAG 模型则会把向量用于相似度检索。
4. **调试方式**：看 shape 是否一致、mask 是否正确、logits 是否异常、相似度分布是否过于集中。

### 最小验证实验

```python
# 伪代码：用 shape 跟踪 FFN 前馈神经网络 是否真的理解到位
tokens = tokenizer("hello agent")
x = embedding(tokens)                 # [seq_len, hidden_size]
for layer in transformer_layers:
    x = layer.self_attention(x)        # token 之间交换上下文信息
    x = layer.ffn(x)                   # 每个 token 内部做非线性特征变换
logits = lm_head(x[-1])                # 只用最后一个位置预测下一个 token
next_token = argmax(logits)
```

### 常见落地场景

- 做 RAG 时，Encoder-only 或 Embedding 模型用于“把问题和文档变成可比较向量”。
- 做工具调用时，Decoder-only 模型根据 prompt 中的 schema 预测结构化 JSON/XML。
- 做性能优化时，KV Cache、batching、量化、LoRA 会影响推理成本和部署策略。

## 11. 针对 `FFN 前馈神经网络` 的专项排查

学习或实现 **FFN 前馈神经网络** 时，可以用下面的方式检查自己是否真正掌握：

- **形状检查**：是否能说清输入和输出的 shape，例如 `[batch, seq_len, hidden_size]`、`[seq_len, vocab_size]`。
- **信息流检查**：是否能说明一个 token 的信息如何影响另一个 token，哪些位置因为 mask 看不到未来。
- **训练/推理差异检查**：训练时通常并行计算整段序列，推理时则逐 token 生成，并通过 KV Cache 复用历史键值。
- **和 RAG 的连接**：如果本主题产出的是 embedding，要关注相似度；如果产出的是 logits，要关注下一个 token 概率。
