# 沙箱、权限与工具执行安全

> 所属分类：Backend / Deploy / Network  
> 修订版本：v6 Kafka 补全融合版  
> 质量要求：本文件只解释本知识点，不复用其他知识点的原理段；示例尽量给出代码、伪代码、命令或配置。

## 1. 总体性概念

沙箱和权限控制限制 Agent 工具执行范围，防止越权、误操作和注入。


## 2. 原理性解释

- 工具描述不是安全边界。
- 代码执行要限制文件、网络、CPU、内存、时间。
- 数据库工具要最小权限。
- 高风险操作要 allowlist 或人工确认。
- 所有工具调用要审计日志。

### 沙箱和权限控制是工具型 Agent 的安全边界

当 Agent 能执行代码、读写文件、访问网络或调用业务系统时，必须限制权限。沙箱的目标是把可执行行为限制在允许范围内，例如文件路径白名单、网络访问限制、超时、资源配额、命令黑名单和审计日志。

```text
LLM 决定动作 ≠ 系统必须执行动作
```

中间必须有 policy layer 判断动作是否安全、是否需要用户确认、参数是否越权。

## 3. 机制流程

1. 模型选择工具。
2. 权限层校验。
3. 参数过滤。
4. 沙箱执行。
5. 记录审计。

### 工具执行安全流程

```text
模型提出 tool_call
  ↓
Schema 校验
  ↓
权限策略检查
  ↓
路径/参数规范化
  ↓
沙箱中执行，限制 CPU/内存/时间
  ↓
记录审计日志
  ↓
返回脱敏结果
```

对于删除文件、发邮件、付款、修改数据库等高风险动作，应要求显式用户确认，并提供可回滚或审计机制。

## 4. 类比理解

给 Agent 工具像给实习生系统权限，必须最小权限和留痕。

## 10. 更细的工程拆解

**沙箱、权限与工具执行安全** 需要放在“请求从客户端到服务再到下游依赖”的完整路径中看：

1. **入口层**：浏览器、客户端、代理、负载均衡、网关。
2. **服务层**：HTTP/RPC Handler、业务逻辑、连接池、缓存、数据库、MQ。
3. **运行层**：容器、Compose/Kubernetes、环境变量、挂载卷、网络策略。
4. **观测层**：日志、指标、trace、健康检查、告警。

### 最小部署/排障清单

```bash
# 1. 看容器是否运行
docker ps

# 2. 看端口是否监听
netstat -ano | findstr 9092

# 3. 看服务日志
docker logs <container>

# 4. 用 curl 验证入口
curl -v http://localhost:8080/health
```

### 工程落地要点

- 网络问题要分层排查：DNS、端口、代理、协议、认证、应用日志。
- Docker/Compose 里路径、端口、环境变量最容易出错，尤其 Windows 路径要注意冒号和绝对路径。
- 只要是线上服务，就必须有健康检查、结构化日志和关键指标，否则出错时只能猜。

## 11. 针对 `沙箱、权限与工具执行安全` 的专项排查

后端部署和网络问题必须分层定位。检查 **沙箱、权限与工具执行安全** 时：

- **客户端层**：请求地址、协议、端口、DNS 是否正确。
- **代理层**：正向/反向代理、网关、路径重写、header 转发是否正确。
- **服务层**：进程是否启动、端口是否监听、健康检查是否通过。
- **依赖层**：数据库、Redis、MQ、外部 API 是否可达。
- **观测层**：日志、指标、trace 是否能定位到失败点。
