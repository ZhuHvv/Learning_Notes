# 正向代理与反向代理

> 所属分类：Backend / Deploy / Network  
> 修订版本：v6 Kafka 补全融合版  
> 质量要求：本文件只解释本知识点，不复用其他知识点的原理段；示例尽量给出代码、伪代码、命令或配置。

## 1. 总体性概念

正向代理代理客户端访问外部资源；反向代理代理服务端接收外部请求并转发内部服务。


## 2. 原理性解释

- 正向代理隐藏客户端。
- 反向代理隐藏服务端。
- 反向代理可做负载均衡、TLS 终止、路径转发。
- SSE 经过代理要注意 buffering。

### 正向代理代理客户端，反向代理代理服务端

正向代理是客户端为了访问外部资源而使用的代理，目标服务器通常不知道真实客户端；反向代理部署在服务端入口，客户端访问的是代理，由代理转发到后端服务。Nginx、网关、负载均衡常属于反向代理。

```text
正向代理：Client → Proxy → Internet
反向代理：Client → Gateway/Nginx → Backend Services
```

## 3. 机制流程

1. 客户端请求代理。
2. 代理转发。
3. 目标服务响应。
4. 代理返回。

### 反向代理请求流程

```text
用户访问域名
  ↓
DNS 解析到 Nginx/网关
  ↓
TLS 终止、鉴权、限流、日志
  ↓
按 path/host 转发到后端服务
  ↓
返回响应
```

部署 SSE/WebSocket 时要特别检查反向代理缓冲、超时和协议升级配置。

## 4. 类比理解

正向代理像代购，反向代理像商场前台。

## 5. 应用举例 / 代码或伪代码

    proxy_pass http://backend:8080/;
}

## 10. 更细的工程拆解

**正向代理与反向代理** 需要放在“请求从客户端到服务再到下游依赖”的完整路径中看：

1. **入口层**：浏览器、客户端、代理、负载均衡、网关。
2. **服务层**：HTTP/RPC Handler、业务逻辑、连接池、缓存、数据库、MQ。
3. **运行层**：容器、Compose/Kubernetes、环境变量、挂载卷、网络策略。
4. **观测层**：日志、指标、trace、健康检查、告警。

### 最小部署/排障清单

```bash
# 1. 看容器是否运行
docker ps

# 2. 看端口是否监听
netstat -ano | findstr 9092

# 3. 看服务日志
docker logs <container>

# 4. 用 curl 验证入口
curl -v http://localhost:8080/health
```

### 工程落地要点

- 网络问题要分层排查：DNS、端口、代理、协议、认证、应用日志。
- Docker/Compose 里路径、端口、环境变量最容易出错，尤其 Windows 路径要注意冒号和绝对路径。
- 只要是线上服务，就必须有健康检查、结构化日志和关键指标，否则出错时只能猜。

## 11. 针对 `正向代理与反向代理` 的专项排查

后端部署和网络问题必须分层定位。检查 **正向代理与反向代理** 时：

- **客户端层**：请求地址、协议、端口、DNS 是否正确。
- **代理层**：正向/反向代理、网关、路径重写、header 转发是否正确。
- **服务层**：进程是否启动、端口是否监听、健康检查是否通过。
- **依赖层**：数据库、Redis、MQ、外部 API 是否可达。
- **观测层**：日志、指标、trace 是否能定位到失败点。
